# 大模型原理综述：从 Transformer 到多模态、推理与 Agent

## 摘要

大语言模型（Large Language Models, LLMs）已经从“会续写文本的超大神经网络”，演化为具备指令遵循、复杂推理、多模态理解、工具调用和检索增强能力的通用智能接口。尽管外部产品形态快速变化，当前主流技术仍然可以归结为几条稳定主线：以 Transformer 为核心架构，以大规模自监督预训练为基础，以指令微调和偏好对齐为能力塑形手段，并通过检索、工具、长上下文、多模态和稀疏化等工程路径提升能力与性价比。到 2026 年，公开资料显示，主流产品能力正在向**原生多模态、超长上下文、混合/延展推理、Agent 化工具使用**几条方向收敛。([arXiv](https://arxiv.org/abs/1706.03762?utm_source=chatgpt.com "Attention Is All You Need"))

## 关键词

大语言模型；Transformer；预训练；后训练；RLHF；DPO；RAG；MoE；多模态；长上下文；Agent

## 1. 引言

今天所说的“大模型”，通常不是单指一个参数巨大的神经网络，而是一个**由基础模型、后训练流程、外部工具、检索系统和推理时策略共同组成的系统**。其能力来源也不再只是“把参数堆大”，而是“架构设计 + 数据质量 + 训练目标 + 对齐方法 + 推理时增强”的共同结果。现有综述普遍认为，LLM 的发展已经从“预训练规模竞赛”进入“后训练、推理与系统化集成”的阶段。([arXiv](https://arxiv.org/abs/2303.18223?utm_source=chatgpt.com "[2303.18223] A Survey of Large Language Models"))

## 2. 大模型的基本原理

### 2.1 语言建模目标：预测下一个 token

大语言模型最核心的训练目标，仍然是自回归语言建模，即在给定前文的条件下预测下一个 token：

[  
P(x_1,\dots,x_T)=\prod_{t=1}^{T}P(x_t|x_{<t})  
]

这件事看起来简单，但当模型参数足够大、训练数据足够多时，模型会在这个目标下学到语法、事实知识、代码模式、任务格式，甚至一定程度上的推理策略。也就是说，LLM 的很多“智能”并不是显式编程进去的，而是从大规模预测任务中**涌现**出来的。([arXiv](https://arxiv.org/abs/2303.18223?utm_source=chatgpt.com "[2303.18223] A Survey of Large Language Models"))

### 2.2 Tokenization：模型为什么不直接处理“词”或“字”

模型并不直接理解自然语言中的“词义”，它首先把文本切分成 token。token 可以是字、词、词片段，甚至是代码符号。这样做的原因是：自然语言词表无限，但 token 词表可以被限制在一个可训练、可查表的离散空间里。Tokenizer 的设计会影响多语言能力、代码能力、推理稳定性和上下文利用率。虽然 tokenization 常被忽视，但它是大模型工程中的第一层“信息压缩协议”。这一点在综述论文中被视为 LLM 基础设施的重要组成部分。([arXiv](https://arxiv.org/abs/2303.18223?utm_source=chatgpt.com "[2303.18223] A Survey of Large Language Models"))

### 2.3 Transformer：为什么它会成为大模型的主干

Transformer 之所以成为主流，不是因为它概念最优雅，而是因为它在**表达能力、并行训练能力和工程可扩展性**之间取得了极强平衡。它用自注意力机制建模序列中任意两个位置之间的关系：

[  
Attention(Q,K,V)=softmax(\frac{QK^T}{\sqrt{d_k}})V  
]

相较于 RNN，Transformer 更适合并行训练；相较于纯 CNN，它更容易建模远距离依赖。因此，从 GPT、Llama，到今天多数商业模型，底层仍然是 Transformer 或其变体。([arXiv](https://arxiv.org/abs/1706.03762?utm_source=chatgpt.com "Attention Is All You Need"))

## 3. 训练大模型的三阶段框架

### 3.1 预训练：让模型先“会说话、会理解、会补全”

预训练阶段的目标不是让模型直接变成聊天助手，而是让它在海量文本、代码、文档和多种模态数据上形成通用表征。这个阶段通常最耗算力，也最依赖数据清洗、去重、混合配比和训练稳定性。Chinchilla 的研究说明，**模型大小和训练 token 数需要协同扩展**，否则会出现“参数很大但训练不充分”的问题；这也是后来行业越来越重视“高质量数据”而不只是“更大参数”的原因。([arXiv](https://arxiv.org/abs/2203.15556?utm_source=chatgpt.com "Training Compute-Optimal Large Language Models"))

### 3.2 指令微调（SFT）：让模型学会按人类任务格式回答

预训练模型会续写，但不一定会“听话”。因此需要用监督微调（Supervised Fine-Tuning, SFT）让模型学习“问答、总结、翻译、代码解释、结构化输出”等任务格式。InstructGPT 这条路线表明，仅仅把模型做大，并不会自然带来更好的用户意图对齐；相反，加入带示范的数据后，小得多的模型也可能更受人类偏好。Self-Instruct 进一步说明，高质量合成指令数据也可以显著提升指令遵循能力。([arXiv](https://arxiv.org/abs/2203.02155?utm_source=chatgpt.com "Training language models to follow instructions with human feedback"))

### 3.3 偏好对齐：从“会回答”到“更符合人类偏好”

SFT 解决的是“会不会做题”，偏好对齐解决的是“回答是否更有帮助、更安全、更符合期望”。经典路径是 RLHF：先收集人类偏好排序，再训练奖励模型，再用强化学习优化。InstructGPT 是这条路线的代表。后续 DPO 把这一流程简化为一种更直接的偏好优化方法，避免单独显式训练奖励模型和复杂的 RL 过程，因此在工业界和开源社区都非常流行。2025 年的后训练综述也明确把**alignment、reasoning、efficiency**列为后训练阶段的三大主题。([arXiv](https://arxiv.org/abs/2203.02155?utm_source=chatgpt.com "Training language models to follow instructions with human feedback"))

## 4. 当前主流技术栈的关键模块

### 4.1 Scaling Laws：为什么“大”依然重要，但不再只看参数量

大模型能力的提升与参数规模、数据规模、训练计算量存在可观测的缩放规律。但行业已经越来越少把“参数量”当成唯一指标，因为更优的数据配比、训练 token 数、MoE 稀疏激活和更强的后训练，往往能让“更聪明的小激活模型”击败“更笨的大稠密模型”。因此，今天讨论模型规模，必须同时看**总参数、激活参数、训练 token、上下文长度和后训练强度**。([arXiv](https://arxiv.org/abs/2203.15556?utm_source=chatgpt.com "Training Compute-Optimal Large Language Models"))

### 4.2 MoE（混合专家）：主流降本增效路线之一

MoE 的核心思想是：不是每个 token 都调用全部参数，而是通过路由机制，只激活少数专家网络。这样可以在保持较大总参数量的同时，把单次推理成本控制在较低水平。Switch Transformer 是这一方向的经典工作。到近两年，MoE 已从学术概念走向主流产品路线，例如 DeepSeek-V3 公开说明其为强大的 MoE 模型，而 Meta 公开材料也把 Llama 4 描述为原生多模态的 MoE 家族。([arXiv](https://arxiv.org/abs/2101.03961?utm_source=chatgpt.com "Switch Transformers: Scaling to Trillion Parameter Models with Simple and Efficient Sparsity"))

### 4.3 长上下文：把“记忆”从几千 token 拉到几十万乃至百万级

长上下文并不等于真正的长期记忆，但它极大改变了应用设计。过去模型更多依赖参数中“隐式存储”的知识；现在模型可以直接读取长文档、仓库代码、视频转录和多轮工作上下文。GPT-4.1 官方文档给出 1M token 上下文窗口；Gemini 1.5 技术报告强调其能在多模态长上下文上进行细粒度召回与推理；Gemini 3.1 则继续沿着原生多模态推理方向推进。长上下文背后离不开诸如 FlashAttention 这类 IO-aware 优化，它通过改写注意力计算过程降低显存与访存瓶颈。([OpenAI开发者](https://developers.openai.com/api/docs/models/gpt-4.1?utm_source=chatgpt.com "GPT-4.1 Model | OpenAI API"))

### 4.4 RAG（检索增强生成）：把参数知识和外部知识库结合起来

RAG 的思想很直接：模型不必把所有事实都“背在参数里”，而是先检索外部文档，再在检索结果基础上生成答案。这样做有三个关键好处：第一，知识可更新；第二，答案有来源；第三，领域问答更容易落地。RAG 已成为企业知识库问答、客服、法务、科研助手等场景的标准配置。不过研究也显示，长上下文本身并不会自动替代 RAG，二者更像互补关系：前者增加一次性可读入的信息量，后者负责主动找对信息。([arXiv](https://arxiv.org/abs/2005.11401?utm_source=chatgpt.com "Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks"))

### 4.5 工具调用与 Agent：从“生成答案”走向“执行任务”

当模型能够稳定地产生结构化调用、函数参数和多步计划时，它就不再只是聊天模型，而开始像 Agent。公开资料显示，GPT-4.1 强调 instruction following 与 tool calling；Gemini 3.1 官方介绍强调更强的 agentic capabilities；DeepSeek-V3.1/V3.2 也明确强化了 tool usage 和 agent tasks。由此可见，**工具使用**已经从“可选增强”变成主流模型能力定义的一部分。([OpenAI开发者](https://developers.openai.com/api/docs/models/gpt-4.1?utm_source=chatgpt.com "GPT-4.1 Model | OpenAI API"))

### 4.6 推理模型：把“想一想再答”变成显式能力

近两年最明显的变化，是“推理”从隐含能力变成产品级模式。Anthropic 公开把 Claude 3.7 称为首个 hybrid reasoning model，并允许在快速响应与 extended thinking 之间切换；Claude 4 继续沿用 hybrid 模式；DeepSeek-R1 和后续 V3.1/V3.2 系列则把 reasoning-first、thinking/non-thinking 模式作为重要卖点。学术综述也开始把这类模型称为 Large Reasoning Models，说明后训练阶段正在从“对齐”进一步走向“可控推理过程塑形”。([Anthropic](https://www.anthropic.com/news/claude-3-7-sonnet?utm_source=chatgpt.com "Claude 3.7 Sonnet and Claude Code"))

### 4.7 多模态：语言模型正在变成通用输入接口

大模型不再局限于文本。Gemini 3.1 官方模型卡将其描述为原生多模态推理模型，可处理文本、图像、音频、视频与代码仓库；Llama 4 官方材料强调其为首批 open-weight 的原生多模态模型；更早的 Gemini 1.5 技术报告则展示了对多文档、长视频和长音频的联合处理能力。于是，今天的“大模型原理”已经不能只讲 NLP，而必须把视觉、语音、视频编码与语言解码的统一建模也纳入讨论。([Google DeepMind](https://deepmind.google/models/model-cards/gemini-3-1-pro/?utm_source=chatgpt.com "Gemini 3.1 Pro - Model Card"))

### 4.8 参数高效微调：LoRA/QLoRA 为何如此流行

真正把大模型带进普通开发团队的，不是最大的训练集群，而是更便宜的适配方法。LoRA 的思想是在冻结原模型大部分参数的前提下，只训练少量低秩适配矩阵，从而显著降低训练参数量与显存占用。QLoRA 更进一步，把底座模型量化到 4-bit，再在其上训练 LoRA 适配器，论文展示了在单张 48GB GPU 上微调 65B 模型的可行性。对于企业私有化、垂直领域适配和低成本实验，这类 PEFT 方法几乎已经成为默认选项。([arXiv](https://arxiv.org/abs/2106.09685?utm_source=chatgpt.com "LoRA: Low-Rank Adaptation of Large Language Models"))

## 5. 从工程视角看，当前市面上的主流路线是什么

从 2025—2026 年公开发布材料做一个工程归纳，主流产品大致正在向以下几条路线收敛，这里带一点综合判断色彩，但基本符合公开资料趋势。([OpenAI开发者](https://developers.openai.com/api/docs/models/gpt-4.1?utm_source=chatgpt.com "GPT-4.1 Model | OpenAI API"))

### 路线一：Decoder-only Transformer 仍是通用底座

无论是 GPT 系列、Llama 系列，还是多数闭源商用模型，通用文本生成能力的底座仍然以 decoder-only Transformer 为主。这说明在可扩展训练、统一任务格式和自回归生成方面，这条路线仍然最稳。([arXiv](https://arxiv.org/abs/1706.03762?utm_source=chatgpt.com "Attention Is All You Need"))

### 路线二：MoE 成为提高性价比的重要方法

如果说 2023 年大家还在讨论“MoE 是否稳定可用”，那么到 2025—2026 年它已经明显进入主流。其原因很现实：商业系统既要强能力，也要可部署，MoE 提供了“总参数大、单 token 激活成本相对可控”的折中方案。([arXiv](https://arxiv.org/abs/2101.03961?utm_source=chatgpt.com "Switch Transformers: Scaling to Trillion Parameter Models with Simple and Efficient Sparsity"))

### 路线三：后训练的重要性已经不亚于预训练

预训练决定“上限潜力”，后训练决定“能否好用”。SFT、偏好优化、推理强化、拒答策略、结构化输出、工具调用格式，几乎都属于后训练范畴。后训练综述把 reasoning 和 alignment 放到中心位置，本身就说明产业竞争重点已经从“谁的底座更大”转向“谁的后训练更成熟”。([arXiv](https://arxiv.org/abs/2503.06072?utm_source=chatgpt.com "A Survey on Post-training of Large Language Models"))

### 路线四：长上下文、多模态、工具调用正在融合成“系统能力”

过去模型能力常被拆成文本、视觉、检索、工具几个独立模块；现在主流产品更像在做统一的“任务操作系统”。GPT-4.1 强调长上下文与工具调用，Gemini 3.1 强调原生多模态与 agentic 能力，Claude 3.7/4 强调混合推理，DeepSeek-V3.2 强调 reasoning-first 和 agents。也就是说，市场主流已经不再把“大模型”理解为单一聊天接口，而是理解为一个可读、可想、可调工具、可执行工作流的通用推理系统。([OpenAI开发者](https://developers.openai.com/api/docs/models/gpt-4.1?utm_source=chatgpt.com "GPT-4.1 Model | OpenAI API"))

## 6. 大模型为什么会“看起来会思考”

这是很多初学者最关心的问题。严格说，大模型并不像人一样拥有显式逻辑引擎；它更像一个通过海量统计学习获得的“条件生成器”。但当训练数据中包含足够多的推理模式、解释过程、代码执行轨迹和任务分解示例时，模型会学会生成近似推理链条。再加上后训练中的偏好优化、推理奖励和推理时预算控制，模型就会表现出“先分析、再作答”的能力。近年的 reasoning model 进展，本质上就是把这种能力从隐式模式识别，进一步做成可训练、可控制、可产品化的机制。([arXiv](https://arxiv.org/abs/2503.06072?utm_source=chatgpt.com "A Survey on Post-training of Large Language Models"))

---

## 7. 当前仍未解决的核心问题

### 7.1 幻觉没有被根治

模型可以更会“说”，不代表更会“真”。RAG、工具调用和后训练都能降低幻觉，但不能彻底消除。Google DeepMind 在 2025 年发布的 FACTS 基准中指出，被评估模型的整体准确率仍明显低于理想水平，说明事实性依然是核心瓶颈。([Google DeepMind](https://deepmind.google/blog/facts-benchmark-suite-systematically-evaluating-the-factuality-of-large-language-models/?utm_source=chatgpt.com "FACTS Benchmark Suite: Systematically evaluating ..."))

### 7.2 长上下文不等于可靠记忆

上下文窗口变长后，模型确实能读更多信息，但并不意味着它一定会稳定检索到最关键片段。实际系统里，长上下文、RAG、摘要压缩和外部记忆库往往仍需组合使用。([arXiv](https://arxiv.org/html/2411.03538v1?utm_source=chatgpt.com "Long Context RAG Performance of Large Language Models"))

### 7.3 Agent 化带来新的安全问题

一旦模型能调搜索、读文件、写代码、操作电脑，错误就不再只是“一句话答错”，而可能变成“执行了错误动作”。Anthropic 的系统卡就专门讨论了 computer use、prompt injection 等风险，这说明工具型模型越强，系统安全问题越重要。([Anthropic](https://www.anthropic.com/claude-3-7-sonnet-system-card?utm_source=chatgpt.com "Claude 3.7 Sonnet System Card"))

### 7.4 成本与效率始终是产业硬约束

更长上下文、更强推理、更大多模态输入都会迅速拉高显存和延迟。因此 FlashAttention、量化、MoE、LoRA/QLoRA 这类技术不会消失，反而会越来越重要。未来大模型竞争，很大程度上会是“同等质量下谁更便宜、更稳、更好部署”的竞争。([arXiv](https://arxiv.org/abs/2205.14135?utm_source=chatgpt.com "FlashAttention: Fast and Memory-Efficient Exact Attention with IO-Awareness"))

---

## 8. 结论

如果把大模型原理压缩成一句话，可以这样概括：

> **大模型的本质，是以 Transformer 为底座，通过海量自监督预训练获得通用表征，再通过后训练、检索、工具、多模态和推理时增强，把“统计语言模型”逐步塑造成“可执行复杂任务的通用智能系统”。** ([arXiv](https://arxiv.org/abs/1706.03762?utm_source=chatgpt.com "Attention Is All You Need"))

从当前公开资料看，未来几年最主流的方向大概率不会是单纯“继续堆参数”，而是以下几条路线的组合：**更高质量的数据与后训练、更强的推理能力、更成熟的 Agent 工具链、更原生的多模态融合，以及更可控的效率优化路线。** 这也是今天理解“大模型原理”时最应该把握的主线。([arXiv](https://arxiv.org/abs/2203.15556?utm_source=chatgpt.com "Training Compute-Optimal Large Language Models"))
