## 一、迁移前的链路

```text
浏览器 / App
    |
    | 访问 https://grayprice.umetrip.com
    | 默认走 443 端口
    v
阿里云 DNS
    |
    | 解析 grayprice.umetrip.com -> 旧 Nginx 公网 IP
    v
旧 Nginx
    | 监听 80 / 443
    |
    | 443: 接收 HTTPS 请求
    | 80 : 可选，做 HTTP -> HTTPS 跳转
    v
旧 Spring Boot 集群
    | 例如监听 8080
    v
业务处理
```

## 三、端口流转图

这是你刚刚问的重点：为什么是 80 / 443 / 8080。

```text
[用户浏览器]
    |
    | https://grayprice.umetrip.com
    | 默认目标端口 = 443
    v
[Nginx:443]
    |
    | 解 TLS / HTTPS
    | 反向代理
    v
[Spring Boot:8080]
    |
    | 处理 Controller / Service / DB
    v
[返回响应]
```

如果用户访问的是 HTTP：

```text
[用户浏览器]
    |
    | http://grayprice.umetrip.com
    | 默认目标端口 = 80
    v
[Nginx:80]
    |
    | 301/302 重定向到 https://grayprice.umetrip.com
    v
[Nginx:443]
    |
    | 再转发到 Spring Boot:8080
    v
[业务处理]
```

## 四、职责拆分图

这个图最适合理解“每一层到底在干嘛”。

```text
grayprice.umetrip.com
        |
        v
+------------------+
|   阿里云 DNS      |
|------------------|
| 负责域名解析      |
| 决定去哪个公网IP  |
+------------------+
        |
        v
+------------------+
|      Nginx       |
|------------------|
| 监听 80/443      |
| 接 HTTPS         |
| 转发请求给后端   |
+------------------+
        |
        v
+------------------+
|   Spring Boot    |
|------------------|
| 监听 8080        |
| 处理业务逻辑     |
| 访问 DB/Redis    |
+------------------+
```

所以可以记成一句：

- **DNS 决定去哪里**
    
- **Nginx 决定转给谁**
    
- **Spring Boot 决定怎么处理**

## 五、迁移时真正发生变化的是哪一层

用户眼里没有变化：

```text
https://grayprice.umetrip.com
```

变化的是这条映射关系：

### 迁移前

```text
grayprice.umetrip.com -> 旧Nginx公网IP
旧Nginx -> 旧Spring Boot集群
```

### 迁移后

```text
grayprice.umetrip.com -> 新Nginx公网IP
新Nginx -> 新Spring Boot集群
```

也就是说：

- **域名没变**
    
- **用户访问方式没变**
    
- **变的是 DNS 指向和 Nginx 后端目标**

## 六、一个更具体的例子

假设：

- 旧 Nginx 公网 IP：`1.1.1.1`
    
- 新 Nginx 公网 IP：`2.2.2.2`
    
- 新 Spring Boot 内网 IP：`10.10.2.15:8080`
    

那迁移后就是：

```text
浏览器访问:
https://grayprice.umetrip.com

DNS解析:
grayprice.umetrip.com -> 2.2.2.2

连接:
浏览器 -> 2.2.2.2:443

Nginx转发:
2.2.2.2:443 -> 10.10.2.15:8080
```

## 七、你们迁移时 Nginx 配置大概长这样

### 80 端口：只做跳转

```nginx
server {
    listen 80;
    server_name grayprice.umetrip.com;
    return 301 https://$host$request_uri;
}
```

### 443 端口：正式接流量

```nginx
server {
    listen 443 ssl;
    server_name grayprice.umetrip.com;

    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/private.key;

    location / {
        proxy_pass http://10.10.2.15:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

这段配置的含义就是：

- 用户访问 `443`
    
- Nginx 终止 HTTPS
    
- 再把请求转给内网的 Spring Boot `8080`

## 九、一句话记忆

**80/443 是给“用户访问域名”用的标准 Web 入口端口，8080 这类端口通常是给 Spring Boot 在内网提供服务用的；迁移时只要把域名继续接到新的 Nginx 80/443，再由 Nginx 转发到新的 Spring Boot 8080，就能保持原域名访问不变。**
